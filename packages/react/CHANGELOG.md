# @clock-ui/react

## 0.2.0

### Minor Changes

- [#21](https://github.com/clock-ui/clock-ui/pull/21) [`d2dd89b`](https://github.com/clock-ui/clock-ui/commit/d2dd89bf5b74d2386219ccd82051a2f0dc50a453) Thanks [@latamaosadi](https://github.com/latamaosadi)! - Fix clock accuracy, widen framework support, and add accessibility.

  **Accuracy**
  - Sweep mode no longer renders half a second behind the wall clock. `updateSweep`
    applied a `-500ms` offset to a millisecond value read from a second, unadjusted
    `Date`.
  - `getTime()` now preserves milliseconds when a timezone is set. `toLocaleString`
    truncates to whole seconds, so every timezone-aware clock previously fell back
    to whole-second stepping and could not sweep at all.
  - Tick mode samples the wall clock every 100ms instead of on every animation
    frame, cutting ~60 `Date`/`Intl` constructions per second per clock down to 10.

  **Compatibility**
  - `@clock-ui/react` now supports React 18 and 19. The peer range was `^19.2.0`,
    which excluded React 18 entirely as well as React 19.0 and 19.1.
  - `@clock-ui/vue` declares `vue ^3.5.0`. The components rely on reactive props
    destructure, which is Vue 3.5+; on 3.4 the clock rendered once and froze.

  **Accessibility**
  - The clock is `role="img"` with an `aria-label` carrying the readable time; the
    face and its contents are `aria-hidden`.
  - `prefers-reduced-motion` is honoured. Because all motion here is
    JavaScript-driven, a consumer's own media query could not disable it — sweep
    now falls back to ticking and the tick easing is skipped.

  **New**
  - `<clock-ui>` custom element at `@clock-ui/dom/element`, for Svelte, Solid,
    Angular, Astro, Qwik, and plain HTML.
  - A date window on `@clock-ui/dom` and `@clock-ui/react`, which previously
    accepted `hideDate` and ignored it. React accepts `children` for it; Vue keeps
    the existing `#info` slot.
  - Prop types are exported from `@clock-ui/react` and `@clock-ui/vue`.
  - `tickDuration` controls how long the second hand takes to swing to each mark
    (default `600`, `0` snaps with no swing). Previously a hard-coded constant
    with no way to reach it. Available as the `tick-duration` attribute on
    `<clock-ui>`.

  **Packaging**
  - `keywords` added — the packages were absent from npm search entirely.
  - `exports` now carry a `types` condition, fixing resolution under
    `moduleResolution: "bundler"` and `node16`.
  - `sideEffects` declared so bundlers can tree-shake.

  **Fixes**
  - `LiveClock` now renders a fixed 12:00:00 on the server and fills in the real
    time on mount. The React package seeded its state from the current time, so
    the server and the client disagreed about every hand angle and React reported
    a hydration mismatch. Vue already behaved this way; the two now match.
  - The 13 per-element colour overrides are registered with `@property`, so they
    appear in devtools and editor autocomplete instead of being invisible until
    you read the stylesheet. The syntax is universal on purpose — a typed syntax
    requires an initial value, and that would defeat every fallback chain.
  - `@clock-ui/react` now forwards `className` and `style` to the clock's root
    element. Both were silently dropped, so every documented theming recipe
    (`className="dark-clock"`) was a no-op. Vue was unaffected — it falls
    attributes through automatically.
  - `@clock-ui/dom` declared `sideEffects: ["**/*.css"]`, which let bundlers
    tree-shake `import "@clock-ui/dom/element"` out of production builds
    entirely — the custom element worked in dev and silently vanished when
    built. The element module is now marked side-effectful.
  - Switching timezone now takes effect immediately in tick mode. Hours and
    minutes only refreshed at the start of a minute, so `setTimezone()` could
    show the old time for up to 60 seconds.
  - `@clock-ui/dom/element` no longer throws when imported on the server.
    `class ClockUIElement extends HTMLElement` was evaluated at module scope, so
    any SSR framework that pulled it into the server bundle — Nuxt, Next,
    SvelteKit, Astro, Qwik — crashed on import.
  - `<clock-ui>` mirrors every attribute as a property. It previously observed
    attributes only, so frameworks that set properties instead — Solid, Lit,
    Angular's `[prop]` binding, React 19 — were silently ignored.
  - The `exports` map is now generated by the build. It was being hand-written in
    `package.json` and silently reverted on every `bun run build`, which put the
    `types` entry back on the CJS declaration.
  - `LiveClockUI.setTimezone()` left `options.timezone` stale.
  - Vue's timezone watcher ignored the prop being cleared back to local time.
  - React's `BaseClock` re-rendered on every frame and computed hand shadows from
    the previous frame's angles.
